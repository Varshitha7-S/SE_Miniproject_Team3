# Branch Coverage Report — Hostel Management System

## 1. Introduction

This report presents the branch coverage analysis performed for the Hostel Management System (HMS) backend.

Branch coverage measures whether the different possible outcomes of conditional expressions have been executed during automated testing.

The analysis uses the branch coverage results generated by Jest during the coverage-enabled test execution.

## 6. Server Startup Branch Coverage Limitation

The `src/server.js` file has 0% branch coverage because the existing Jest API tests exercise the Express application through `createApp()` in `src/app.js`.

The test suite does not execute the actual server startup process.

The startup file includes conditional logic related to:

- Environment configuration.
- JWT secret validation.
- Database connection success or failure.
- HTTP server initialization.

These paths were outside the execution scope of the current API test suite.

The 0% result is therefore documented as a testing-scope limitation rather than a failed application test.

## 7. Branch Coverage Limitations

The following limitations were identified:

1. The current automated suite primarily tests backend API and integration behaviour.
2. Not every possible conditional outcome in the backend source code is exercised.
3. Database connection and validation branches have opportunities for additional testing.
4. Server startup behaviour was not executed during the coverage run.
5. The report reflects the coverage obtained from the existing automated tests and does not claim complete branch coverage.
